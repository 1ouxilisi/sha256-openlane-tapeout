五、两个错误的性质（能说到哪 / 不能说成什么）
- DRT-0218「Guide is not connected to design」是**顺序问题**：二极管插在详细布线之后，
  guide 体系已与物理连线绑定，重跑 GRT 也补不回来。
- GRT-0226「Type2 ripup not type L」是**工具内部错误**：插完二极管后的重布线阶段，
  OpenROAD 的 ripup 遇到非 L 类型的线网。换起点（22-global / 20-）、
  换参数环境（有无 layer adjustment）都复现。
- 因此：**「修法可行」与「版图已修」是两件事**。
  前一份证据证明前者（147 个二极管、复测 0/0），
  本份证据说明后者这条路本轮走不通：我拿不出「修好的 GDS」。
- 天线违例数随阶段变化，须写清口径：最终详细布线后 67 net / 87 pin；
  全局布线后（尚未详细布线）71 net / 92 pin。页面与报告一律以 67/87 为准。

六、要真修，下一步只有两条（都超出「改一个数字」的范围）
1) 改配置从头重跑整条 flow：在 config 里打开 GRT_REPAIR_ANTENNAS = 1
   （本 run 为 0，第 153 行），让修正在正式流程的 GRT 阶段由 OpenLane 自己调用——
   但同一份 OpenROAD 修法代码在此设计上已出现 GRT-0226，成功率未知，且要重跑
   placement→routing→fill→GDS→signoff 全部步骤。
2) 从电路侧消除违例：对首条违例 net _02246_ 这类长 met4 段，改布局/改层分配或加缓冲，
   从源头降低天线比，再重跑布线。这属于设计改动，不是验证动作。
无论走哪条，现有 XOR（21 制造层全 0）、两套 DRC（0/0）、密度（0/0）、
LVS（Circuits match uniquely）四组结论都指向旧版图，必须重跑后重新举证。

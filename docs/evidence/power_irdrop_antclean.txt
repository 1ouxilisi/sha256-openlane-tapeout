五、它证明什么、不证明什么
--------------------------------------------------
证明：在同一份最终 ODB（含天线二极管与 fill）上，功耗与电源网络压降都真的算过一遍，
      三个工艺角的数都能从上面的命令重跑出来。
不证明：
1) 不是硅上实测，是工具按 liberty 内部功耗表 + 向量无关活动率假设算出来的估算；
   活动率换一档总数就动（tt 角 9.16 / 9.57 / 10.7 mW），所以只能当工程估算，不能当签核数。
2) iRdrop 是静态压降：电流来自 PDNSim 自己的默认估算，没有 di/dt 动态项，
   没有封装 / 焊盘 / 外部供电模型；PDN 用的是 OpenLane 默认条纹网格，没做网格优化对比。
3) 功耗没有做时钟树功耗优化（时钟占 43.6%），也没做多阈值 / 电源门控之类的手段。

六、本次用到但没在上一版记录里出现的两个坑
--------------------------------------------------
1) analyze_power_grid 先读 ODB 不读 liberty 时，报告会「跑成功」但 Supply voltage 是 0.00e+00 V，
   全部 IR drop 打印 0——看起来像「没有压降」，其实是没电源。必须按 OpenLane irdrop.tcl 的顺序
   先 read_liberty（工作条件里带 1.8 V），再 analyze。
2) report_power 一次进程只能干净地跑一个 corner；想在一次脚本里循环两个 liberty 会报
   invalid command name "reset_path"，所以 ss 与 ff 是分两个进程跑的。

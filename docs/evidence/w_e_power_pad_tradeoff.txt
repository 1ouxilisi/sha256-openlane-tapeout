W/E 边补电源 pad 的取舍：先把账算清楚，再决定要不要动
================================================================
日期：2026-11-15
性质：决策备忘（不是版图变更，也没改任何 GDS）
背景：A 路径（core 电源环）已在 chip13 / chip14 完成并上线；B 路径
      （W/E 边补电源 pad）一直挂着没拍板。本文只做取舍核算。

1. 实测 pad 账（来源 padmap.json，100 条，逐条 bbox 统计）
--------------------------------------------------------
映射规则：bbox 82×200 或 75×200 为 N/S 边 pad（竖直插入），
          bbox 200×82 为 W/E 边 pad（水平插入）。
槽位：每边 25 个，pitch 81，起点 200，即 200 + 81k（k=0..24），末位 2144。

边    总 pad   gpiov2   电源 pad                        备注
N       25       23     PAD_pwr_hv(200–275) + PAD_gnd_hv(281–356)
S       25       23     PAD_gnd_lv(2069–2144,rot2) + PAD_pwr_lv(2150–2225,rot2)
W       25       25     无
E       25       25     无
合计   100       96     4（2 高压 + 2 低压）

结论一：W/E 两边共 50 个 pad 全为 PAD_gpiov2，确认无电源 pad；电源 pad
        只有 4 个，N 边一对 hv（3.3V IO 域），S 边一对 lv（1.8V core 域）。
        （此前页面里「W/E 共 50 个位置全是信号 pad」的口径经复算成立。）

2. 两个电源域、两个单点入口
--------------------------------------------------------
- 3.3V IO 域（VDDIO / VSSIO）：注入点只有 N 边一对 hv pad。
  这 96 个信号 pad 每颗都有自己的 VDDIO / VSSIO pin，这些 pin 靠
  pad 缝里的 1440 条桥接段连成侧总线（其中 VDDIO 192 条、VSSIO 192 条），
  再由 N 边 hv pad 注入。
- 1.8V core 域（VCCD/VCCHIB / VSSD/VSSA → VPWR/VGND）：注入点只有
  S 边一对 lv pad（chip13 用 N 边出线，chip14 加 S 边镜像出线）。

结论二：「W/E 边 50 个 IO 的电源悬空」这个说法不准确。它们不是悬空，
        是**整条 3.3V 侧总线只有一个注入点（N 边）**。缺的是冗余入口和
        远端压降余量，不是连接。

3. 三个可动的杠杆，以及它们各自能改多少
--------------------------------------------------------
core 侧现在的电流路径分两段：

  (a) 环→stripe 接头：VPWR 4 条 met4 横条（x862–905，43 µm，宽 1.6），
      各 27 方，4 条并联 ≈ 6.75 方等效；VGND 4 条 met5 横条（x870–900，
      30 µm），各 18.75 方，并联 ≈ 4.7 方。
  (b) 环本身：VPWR 中心线 x/y = 862 / 1563（边长 701 µm，宽 1.6），
      VGND 中心线 870 / 1555（边长 685 µm，宽 1.6）。

假设：电流单侧绕行（保守简化），方数 = 长度 / 宽度。

情形                          环上最远绕行      等效方数(VPWR)
现状：仅 N 边一个入口          1402 µm          876 方
加 W 边一个入口（对角两口）     701 µm           438 方
环宽 1.6 → 3.2（不加入口）     1402 µm / 3.2    438 方
加 W 入口 + 环宽 3.2           701 µm / 3.2     219 方

结论三：单看方数，接头的 6.75 方在环的 438–876 方面前可以忽略（差 60–130 倍）。
        所以「多打几个 pad」不会改变接头，只改变环的绕行距离；而**加宽环
        和加入口是同一量级的两个杠杆（都是约 2 倍）**，加宽还不要 IO 代价。

这就是 B 路径的定位问题：把它说成「补电源 pad」会让人以为这是唯一解，
实际上它是三件事里的第三件。

4. 电流预算：目前没有可信输入（硬证据）
--------------------------------------------------------
ctsfix3 的 reports/metrics.csv 里七角功耗字段（µW）：
  power_typical_internal  0.00718
  power_typical_switching 0.00232
  power_typical_leakage   0.00000176
合计 ≈ 0.0095 µW。按 I = P / 1.8 V 折算约 5 nA，显然不是真实功耗——
这是默认活动率下的估计，没有真实激励和 SPEF 关联。

结论四：拿这组数去定 PDN 宽度和入口数量，会得出荒谬结论。要做电流预算，
        得先补「真实负载活动率 / 向量集」和「带 SPEF 的功耗分析」。
        在这一步之前，任何「够不够」的定量结论都不能写。

同时要说明：不管方阻取哪个合理值，几百方的环形路径都撑不住 mA 级电流。
chip14 这版的定位仍然是「拓扑闭环 + 几何合法」，不是供电合格。

5. 真要动 B 路径，完整代价清单
--------------------------------------------------------
以「W、E 各替换 2 个 gpiov2 为 lv 对」为例（这是页面早先写的 96→92 方案）：

- 信号数 96 → 92，产品定义要跟着改；
- padframe 重新生成（gen_pads4.py 的实例化规则、PITCH=81 START=200 N=25 DIE=2425）；
- 1440 条 pad 缝桥接段必须重算（每条桥依赖相邻 pad 的电源 pin，换 pad 会改 pin 集合）；
- core 环与出线要重排：VPWR 环左/右竖条（x861.2–862.8、x1562.2–1563.8）和
  VGND 环左/右竖条（x869.2–870.8、x1554.2–1555.8）横贯整个高度，
  任何从 W/E 进来的水平走线都要跨过它们：接自家网的条可直并，
  跨异网的条必须换层（met5 竖条 vs met4 竖条，层不同可跨但不可打 via）；
- flat DRC 全量重跑一次（约 2300 s，8 GB 内存峰值约 41%，不能并发）；
- pad 级 LVS 在本环境不可判（netgen sky130A_setup.tcl 第 378 行只认两种
  IO cell，换 pad 后没有等价校验手段），只能靠 DRC + 并查集兜；
- 证据文档、页面、README、图要同步改一轮。

收益侧（按第 3 节）：3.3V 域多一个注入点（远端压降从「N 单点到对角 1402 µm」
降到约 701 µm），core 域的收益为零——core 环已经由 S 边 lv 对供上了。

结论五：B 路径如果做，理由应该是「3.3V IO 域单点注入的冗余/压降」，
        而不是「core 电源不够」。这两件事的优先级和决策人不同。

6. 建议顺序（先便宜后贵，先无代价后有代价）
--------------------------------------------------------
第 0 步（不花 IO，不花 DRC）：补电流预算。真实活动率 + SPEF 功耗，
        否则第 1、2 步都没有判据。
第 1 步（不花 IO）：环加宽 1.6 → 3.2 µm。约 2 倍改善，代价是环与
        VGND 右侧竖条（x1554.2–1555.8）间距重排 + 一次全量 DRC。
第 2 步（花 2–4 路信号）：W/E 加 hv 对（不是 lv 对），给 3.3V 域
        第二个注入点。这是在解决 IO 供电冗余，不是 core 供电。
第 3 步（结构性）：多层并联（met3 + met4/met5 双环），或干脆改 PDN
        拓扑（两侧各一条宽 bus + 多条窄环）。这已经不是「补 pad」量级。

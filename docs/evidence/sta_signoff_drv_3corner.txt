设计规则类检查（DRV）：max transition / max fanout / max capacitance，三 corner，新旧两版同脚本对照
===============================================================================================

一句话结论
----------
时序（setup / hold）在新版三 corner 全部 MET。但同一份 SDC 里写的两条设计规则约束——
set_max_transition 0.75、set_max_fanout 10——在新版和旧版都没有满足。
所以准确说法是「时序通过，DRV 未清」，不是「signoff 通过」。
这条我原来没查，是补上来的，放在这里作废掉任何一句「时序 MET 就算过签核」的说法。

约束不是你猜的，是 SDC 原文里写的
------------------------------
文件：designs/sha256_v7b/runs/tapeout16/tmp/20-sha256_axil.sdc
第 212 行：set_max_transition 0.7500 [current_design]
第 213 行：set_max_fanout     10.0000 [current_design]
这两条由 OpenLane 的 base.sdc 模板生成（MAX_TRANSITION_CONSTRAINT=0.75），
属于本 run 自己的约束，不是工具默认值，也不是我为了凑一个结论临时设的。
max_capacitance 的限值来自 liberty（每个 pin 各不相同，量级 0.03–0.08 pF）。

怎么跑的（和 sta3c.log / sta3c_old.log 完全同一条链）
--------------------------------------------------
读 LEF（merged.max.lef）→ define_corners Slowest/Typical/Fastest → 三份 liberty
（ss_100C_1v60 / tt_025C_1v80 / ff_n40C_1v95）→ read_verilog 网表 → link_design sha256_axil
→ read_sdc 20-sha256_axil.sdc → set_propagated_clock → 三份 SPEF
→ 逐 corner：report_check_types -max_slew / -max_capacitance / -max_fanout，
再加一次 -max_slew -max_capacitance -max_fanout -corner <c> -violators -verbose 打印每个违例 pin。
脚本：/tmp/signoff_new/sta3c_chk.tcl（新版）与 sta3c_chk_old.tcl（旧版，只换网表与 SPEF，
nom 角用官方 max SPEF 代替——和 sta3c_old.log 的处理完全一致）。

怎么读这组数（不做美化）
----------------------
1. DRV 不是新版才坏：旧版同样 353 / 151 / 143 条违例，时钟叶子 buffer 扇出 25 也早超限。
   这条从头到尾都没被清过，之前的「时序 MET」只覆盖 slack，不覆盖 DRV。
2. 新版确实更差：fanout 违例 143 → 219 条，慢角 slew 违例 210 → 255 条，最差扇出 25 → 27。
   合理解释：天线修复插了 430 个二极管、重做了全局布线与详细布线、时钟树随之重做，
   每个时钟叶子 buffer 多带了 2 个负载。这是修复天线付出的代价，和 setup 少 0.156 ns 是同一笔账的两面。
3. 但 setup 仍正、hold 仍正、TNS 0：DRV 违例在 18 ns 周期下没有把时序打死，
   它意味着「这版不能直接当量产 signoff 交出去」，而不是「这版跑不起来」。
4. 扇出超限集中在时钟叶子 buffer 与 input9/input11 这类输入驱动 pin，属于结构性问题，
   不是随机噪声——要清就得回头改时钟树结构或加 buffer 层级，不能在 STA 里改约束糊过去。

它不证明什么
------------
- 不证明这版过了签核：DRV 三 corner 都有违例，最大扇出 27 vs 限 10。
- 不证明旧版过了签核：旧版同样违例，只是数量少一些。
- 不证明这些违例可以被忽略：18 ns 周期下时序仍有正 slack，但 DRV 超限在真实工艺里对应
  电迁移、串扰、时钟偏斜风险，属于必须清的项目，不是可选优化。
- 不证明原因已定：扇出增加与天线修复的因果关系是我根据动作顺序提出的解释，
  没有做过对照实验（比如只插二极管不重布线）来隔离变量。
- 没有做 max_capacitance 之外的电气规则：没有 ERC、没有 iRdrop、没有每个单元的逐管等价检查。
- 没有重跑功耗/面积：这里只补 DRV，功耗与面积仍以 sta_signoff_3corner.txt 为准。

复现
----
同环境同脚本即可：
  openroad -no_init -no_splash -exit /tmp/signoff_new/sta3c_chk.tcl      > sta3c_chk.log 2>&1
  openroad -no_init -no_splash -exit /tmp/signoff_new/sta3c_chk_old.tcl  > sta3c_chk_old.log 2>&1
计数口径：以日志里 "-- corner <c> violators" 段内每个 "Pin <name>" 块为一条违例，
块内首行 "max slew / max fanout / max capacitance <limit>" 决定类别。

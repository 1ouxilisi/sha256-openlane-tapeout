====================================================================
一、一句话结论
====================================================================

上一轮（第三次补正）判死的「接二极管脚 vs 跨行 li1 feedthrough」结构性二选一，这一轮被绕开了：
把详细布线的起底层从 li1 换到 met1（detailed_route -bottom_routing_layer met1），39 颗开路的二极管脚
改用 met1 接出，不再需要 li1 跨行走线；随后回填 35,327 颗 filler，magic 抽取不再塌缩，
同版 LVS 跑出 Final result: Circuits match uniquely.

这是本项目第一次让下面六件事同时成立：
  跨行 li1 = 0、二极管开路 = 0、布线违规 = 0、filler 完整、端口 94、LVS 通过。

仍然不写「signoff 通过」。理由是第六、七、八节列的四条：STA 未跑、DRC 未跑、
met1 跨行还剩 1 条、整条链只跑过一次。页面口径按用户锁定的写法：时序未测、DRV 未清、
LVS 通过（同版参考）。

====================================================================
二、为什么前四轮都卡在二选一
====================================================================

T2 的做法是「先详细布线、后插二极管」，结果是 39 颗管的 DIODE 脚没有任何金属（见 lvs_t3t4_route.txt）。
T3/T5 让布线器去接这 39 颗脚，脚接上了，但 li1_guard 立刻报 23 条（T5 是 15 条）跨行 li1 —— 
和上一版刚消掉的短接源是同一个东西。T4 想用 filler 把井补回来，filler 一插，li1 大面积并成
node663（bbox 5520,490365;634340,500055），电源又并回去（VGND 843 / VPWR 67,436）。

当时的结论是「布线器把接二极管脚和跨行 feedthrough 绑死」。这个结论对 T2 起点成立，
但它默认了一个前提：bottom layer 只能是 li1。这一轮把这个前提拆掉。

六、T8 的四道判据，逐条可复算
====================================================================

1）跨行 li1：li1_guard.py tmp/eco/eco_it2_t8.def → cross-row li1 = 0，VERDICT PASS
   判据是「NETS 里竖直 li1 段长 ≥ 2,720 dbu（一个标准单元行高）」。
2）二极管开路：def_open.py → open diodes in DEF = 0
3）跨行 met1（这一轮新加的第二道闸）：met1_guard.py → cross-row met1 = 1
     net816  x=634570  y=403070..405790  len=2720
   这条没消掉。它没有把电源短掉，证据是抽取网表里 VGND/VPWR 仍分开（33,988 / 34,018）、
   且 LVS 唯一匹配；但按「met1 做底层会拉出长竖线压电源轨」的旧账（net46 那条
   94 µm met1 竖线），这一条必须写在页面上，不能当 0 处理。
4）端口与实例：TOP_PORTS 94 / TOP_INST 16,572，与参考网表同源（347 颗二极管那一版）。

七、一个必须说清的事实：T7 与 T3 的抽取网表逐字节相同
====================================================================

T7 的 layout_t7.spice 与 T3 的 layout_t3.spice 完全同一份：
  1,711,285 B / md5 092442ffb5d911944c02be38898d83d2（T3 与 T7 两次独立 run 各一份）

这意味着：把 li1 跨行改成 met1 起底，电气拓扑一点没变。反过来说，
T3 那 23 条跨行 li1 在 DEF 里确实存在（li1_guard 抓到），但落到 GDS 抽取层面
并没有造成电源短接 —— T3 的 VGND/VPWR 是 33,988 / 31,630，不是塌缩值。
所以第三次补正里「跨行 li1 是短接源」这句话要收窄成：
  它是短接的必要条件之一，不是充分条件；真正并网的那一版（eco4 / ga，VGND 66,531 / VPWR 0）
  有它，加上 filler 一起才并。
这条更正按用户规矩公开写在这里，旧记录 lvs_short_fix.txt / lvs_t3t4_route.txt 不删不改。

八、仍未闭合（不写 signoff 通过的全部理由）
====================================================================

1）STA 没跑。T8 的时序、DRV（max slew / max cap / max fanout）都没测。T8 相比 T2 多了
   20 颗新二极管的负载与 met1 走线，时序不能沿用旧 ECO 的数字。
2）DRC 没跑。magic 或 klayout 全片 DRC 都没有在 T8 上跑过。
3）met1 跨行 1 条（net816，len=2720）。抽取层面没短接，但几何上是跨了两条相邻全宽 met1 轨
   的高度，需要 DRC 或几何扫描确认它与 VGND/VPWR 轨没有 overlap。
4）只跑了一次，没有做稳定性复现。detailed_route 没有固定 -or_seed，T8 的 DEF 是否可稳定
   复现出同一份，还没验证。这一条直接关系到「别人能复现」，下一轮必须先做。
5）参考网表用的是 net_t2.spice（347 颗二极管那一版）。T8 的实例集 = T2，filler 不参与 LVS 逻辑，
   所以同版；但如果要按最严口径，应从 t8.odb 现出一份 net_t8.spice 再比一次。

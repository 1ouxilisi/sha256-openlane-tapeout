二、这条命令到底做了哪四段
================================================================================

PHASE A  magic -dnull：gds read → load sha256_axil → select top cell →
         extract do local / no capacitance / no coupling / no resistance / no adjust /
         extract unique → extract。跑完打 PHASE_A extract_done。
PHASE B  新开一个 magic 会话（不是同一个进程里接续）：load → ext2spice lvs →
         ext2spice -o <路径>，**不写 ext 名**。上一轮的病根就在这：
         ext2spice -o <输出> <ext 名> 里的 <ext 名> 不存在时，magic 不报错、不落盘，
         回落读当前目录里旧的 sha256_axil.ext。本轮的 B 段没有第二参数，所以没有回落口子。
PHASE C  宿主机 /opt/python3.12 /home/user/lvspkg/prep_lay.py --expect-ports <N>
         端口数不符即 fail（这一步会挡住「端表悄悄少脚」）。
PHASE D  netgen -batch lvs "<版图 spice> sha256_axil" "<基准网表> sha256_axil" <setup> <out>
         取 out 末条 Final result 判 PASS / NOT-PASS。

每段各带超时（A 1800 s、B 900 s、D 1800 s），超时或没打出完成标记就退出并写
summary.txt；不会「挂着等人看」。

三、卡点与定位：空工作目录里 extract 会静默停住
================================================================================

现象（三次，工作目录都是新建的空目录：w_f2v / w_f2v2 / w_t1）：
  日志停在 Processing sha256_axil 之后就没有下文（12,503 / 12,095 / 12,027 B 三份）；
  进程状态 S/R 交替，CPU 时间停在 6–11 s 不再涨；
  VmRSS 恒 420,864 kB；没有子进程；打开的文件只剩 0/1/2（stdin/stdout/stderr）；
  /proc/<pid>/io 的 rchar 停在 44,246,538 不再增长；vmstat 的 r 列恒 0（不是抢不到 CPU）。
  只能 kill -9。

对照 A（同一段脚本，工作目录里已经有 148 个标准单元 .ext）：2 分钟跑通，
  现抽出新的 sha256_axil.ext 19,823,266 B，layout_t6.spice 1,686,735 B / md5 09183c36…。
对照 B（空工作目录 + addpath 指向同一份 148 个 .ext）：仍然停住。
  ⇒ 要求是「这些 .ext 就在当前目录」，不是「addpath 里能找到」。
  （顺带一条命令行事实：magic 的 addpath 只吃一个参数，写两个会报
    Usage: addpath appended_search_path 并让整个 tcl 解析中止。）

所以本轮对外的说法是：magic 抽顶层时，各子单元的 .ext 必须落在 cwd；
缺了它不报错、不写文件、不退出，只是停住。至于 magic 内部为什么走这条路，
本轮没有定位到（见第六节「仍未闭合」）。

================================================================================
四、那 148 个 .ext 从哪来 —— 从 PDK 自己长出来，不需要外部二进制
================================================================================

在干净目录里对 PDK 的 sky130_fd_sc_hd.gds 逐单元重抽：
  gds read /pdk/sky130A/libs.ref/sky130_fd_sc_hd/gds/sky130_fd_sc_hd.gds
  然后对每个 master：load → select top cell → extract do local … → extract
  148 个单元，一个 magic 会话，日志末尾打 CACHE_DONE；
  产出 148 个 .ext，合计 572,151 B（目录 824 KB）。
单单元对照：空目录里 load sky130_fd_sc_hd__inv_1 后 extract → T8_DONE，写出 inv_1.ext。
  说明「单单元抽取」本身不挑目录；挑目录的是顶层那一抽。

⇒ 缓存不是必须从别处拷来的黑盒：它可以从 PDK 重新生成，脚本就在仓库里。
   本轮用的就是这份自己长出来的缓存，没有再依赖 /tmp/n52 的历史残留。

七、复现方法（原文照抄即可）
================================================================================

仓库内脚本：lvs-repro/repro3.sh、lvs-repro/ext.tcl、lvs-repro/sp.tcl、lvs-repro/build_cache.tcl
环境变量与 nix 路径写死在脚本头部（本机 chroot 的固定路径，换机器要改那几行）。

  bash lvs-repro/repro3.sh /tmp/eco/eco_it2f.gds f4 94 /tmp/lvs_it2c/net.spice   # → PASS
  bash lvs-repro/repro3.sh /tmp/eco/eco_it2g.gds g5 93 /tmp/lvs_it2c/net.spice   # → NOT-PASS

退出码：0 PASS / 2 结果不一致 / 3 提取链自己在某一段就失败了（summary.txt 会写 FAIL@哪段）。

AXIL-SPI 小车设计（AXI4-Lite + SPI Master）全流程实跑记录
生成：2026-11-09  环境：云主机 chroot /home/user/openlane-rootfs  OpenLane 1.1.1  sky130A

一、这颗设计是什么
  目的：SHA-256 加速器是"计算核"，只有 AXI4-Lite 寄存器接口；为了证明同一套流程能承接带真实外设协议的 IP，
  另起一颗小设计，接口换成 AXI4-Lite 从口 + SPI Master 主口，规模压到 220 x 220 um，用同一份 PDK、同一套脚本、
  同一条验收口径再走一遍。

  RTL（/designs/axil_spi/src/）：
    axil_regs.v      3,564 B / 103 行    AXI4-Lite 从口三态机 W_IDLE / W_DATA / W_RESP。
                                          读写地址分离（reg_raddr 单独输出），修掉过"读操作把写地址寄存器读走"的 bug。
                                          输出 reg_addr / reg_raddr / reg_wdata / reg_wstrb / reg_we，输入 reg_rdata。
    spi_master.v     2,994 B            mode0（CPOL=0 / CPHA=0）、8 位、半周期由 div 计数决定；
                                          ST_IDLE / ST_SHIFT / ST_DONE；上升沿采 miso、下降沿换 mosi；
                                          输出 sclk / mosi / cs_n / busy / done / rx_data。
    axil_spi_top.v   3,918 B            寄存器映射 0x000 CTRL（bit16 手动启动、bit1 irq_en）、
                                          0x004 DIV、0x008 TXD（写入即启动传输）、0x00C RXD（bit8 fresh）、
                                          0x010 STATUS（bit0 busy、bit1 irq）；irq = rx_fresh & irq_en。

  仿真（sim/tb_axil_spi.v，自建 SPI 从模型：回 0x3C、采 mosi）四项：
    默认读 0xDEADBEEF / DIV 回读 / TXD 写触发后 RXD==0x3C 且从端收到 0xA5 / STATUS busy=0
    结果：TB PASS（$finish at 1,155,000 ps）。
    修过两处：axi_write 任务的 wait(awready&&wready) 死等，改 wait(bvalid)；CTRL 启动位原与 STATUS bit0 撞位，移到 bit16。

三、两次失败与根因（都不是设计问题）
  1) 第一次跑 -tag axspi1，在 Step 0 verilator_lint_check 假失败：linter 日志本身无 ERROR，
     但流程里那句 exec bash -c "grep -i 'Error-NEEDTIMINGOPT' ..." 因为 chroot 默认 PATH 没有 grep 而返回非零，
     下游 generate_reports.py 找不到 power report，抛 IndexError: list index out of range。
     修法：把 coreutils-9.5 / gnugrep-3.11 / bash-5.2p26 的 bin 目录显式写进 PATH 重跑。
  2) 第二次一路跑到 Step 41，Magic DRC 已经 0 条（log 里 COUNT: 0），紧接着的 KLayout DRC 内部报错：
     ERROR: ../../../src/tl/tl/tlFileUtils.cc,979,false / Internal error: tlFileUtils.cc:979 false was not true
     根因：chroot 里 /proc 只是一个空目录，KLayout 启动时读 /proc/self/exe 拿自己的安装路径，取不到就内部断言失败。
     这不是 DRC 脚本或 GDS 的问题——同一份 GDS 用同一份 sky130A_mr.drc、在"先把 /proc/<pid>/exe 软链到真二进制再 exec 同一 pid"
     的写法下能正常跑完（结果 0 条）。
     修法：KLayout DRC 在流程内关掉（RUN_KLAYOUT_DRC 0），改由 /tmp/kl/drc_axspi.sh 单独补跑；流程其余照跑。

八、结论与边界
  这颗小车设计证明的是"流程可承接带 AXI4-Lite + SPI 真实协议接口的设计"，并且全流程可跑完、时序与 LVS 干净。
  不声称 signoff 通过：仍有 5 条 max_fanout 违例和 1 条天线记录，KLayout DRC 是在流程外补跑得到的 0 条。
  也不声称面积/功耗优秀：24.88% 利用率、微瓦功耗都来自"小规模 + 优先跑通"，与 SHA-256 那颗的 40% 利用率、
  pF 级寄生、mW 级功耗不是同一量级，不可横向对比。

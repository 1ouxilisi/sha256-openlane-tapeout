0. 结论
==============================================================
1) 方法先用旧版校准：同一套脚本读旧版官方产物（results/routing/sha256_axil.nl.v
   + mca/process_corner_max/sha256_axil.spef），clk 组最差 setup 得到 +0.5619 ns，
   与此前页面与证据上公布的 +0.5619 逐位一致 —— 说明这次脚本没有漏项。
2) 新版（fixed16：天线修好 + 重新布线 + 430 个二极管）：
     setup 最差角 Slowest = +0.4058 ns
     hold  最差角 Fastest = +0.4096 ns
     TNS = 0.0000
   两角都为正，18 ns 周期（55.56 MHz）仍然成立。
3) 代价：最差 setup 从 +0.5619 变成 +0.4058，少 0.156 ns。这是
   「重新全局布线 + 天线修复 + 重新详细布线」整条动作的净代价，不是二极管单独的代价
   （新版不是「原版 + 二极管」，diode 与布线是同时换的）。hold 反而略好（+0.4021 → +0.4096）。
4) 修正上一版的说法：上一版站点写「估算口径 STA：原版 +9.8329 / 新版 +9.9243」，
   那是 estimate_parasitics -global_routing 的估算值，过于乐观，不能当 signoff。
   同一方法下两侧都掉到 0.4–0.6 ns 量级。以本文件为准。

==============================================================
1. 为什么这次叫 signoff 口径
==============================================================
- 寄生不是估的：OpenROAD 的 rcx 直接从布线后的 DEF 提取，参数与 OpenLane 自己的
  scripts/openroad/rcx.tcl 同形：
      read_lef <merged.角.lef>
      read_def <fixed16.def>
      define_process_corner -ext_model_index 0 X
      extract_parasitics -ext_model_file <rules.openrcx.sky130A.角.calibre> -lef_res
      write_spef <fixed16.角.spef>
  三个角各提取一次，写三份 SPEF（本 run 的 RCX_MERGE_VIA_WIRE_RES=1，因此不带
  -no_merge_via_res）。
- 三个工艺角：ss_100C_1v60（Slowest） / tt_025C_1v80（Typical） / ff_n40C_1v95（Fastest），
  各自读自己那角的 SPEF（read_spef -corner <name>）。
- 约束沿用 run 自己的 20-sha256_axil.sdc（CLOCK_PERIOD 18.0、clock uncertainty 0.25、
  clock transition 0.15、I/O delay 3.6 各端口逐条），set_propagated_clock。
- STA 从网表 + SPEF 起算（与 OpenLane 的 sta/multi_corner.tcl 同形），不是从 ODB、
  也不是从估算寄生起算。

==============================================================
6. 它不证明什么（别拿它说过头话）
==============================================================
- 没有 iRdrop / 电压降分析，没有 EM 检查。
- 没有跑 max slew / max cap / max fanout 违例检查（只报了时序 slack）。
- 没有 ERC，没有金属密度窗口（只有 PDK 的「最小空孔率」那一份 deck）。
- 没有 GDS XOR（旧版上的「21 层全一致」只在旧版成立）。
- 功耗是默认 activity 下的估算，不是带真实翻转率的 signoff 功耗。
- 仍然是「顶层」口径：标准单元内部按库模型算，不做单元内逐管的时序。
- 210 个 driver 无寄生标注，说明这不是逐网 100% 标注的完美提取。

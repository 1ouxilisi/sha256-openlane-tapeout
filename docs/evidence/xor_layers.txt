说明（三行）：
1. 这是对 OpenLane 第 37 步 gds_klayout 的独立重做：该步在流水线里因 KLayout 的 Ruby 引擎在本机 chroot 内初始化失败（tlFileUtils.cc:979）而未产出结论。
2. 方法：用同一套 KLayout 0.29.1 库的 Python 接口（klayout.db），把两份 GDS 的顶层几何按层（layer/datatype）展开后逐层做 XOR，比较几何覆盖，而不是比较多边形条数。
3. 判据：某层 XOR 后的多边形数为 0，即该层两份版图完全一致。

结论：
- 42 个层中，41 层 XOR 为 0：两份 GDS 的几何覆盖完全一致。
- 唯一差异在 81/14（prBoundary，版图边界标记）：A 有 1 个，B 有 0 个。这一层不参与制造，
  而且流水线第 37 步原本就用 -rd ignore=81/14 把它排除在外；第 37 步若未崩溃，这一层也会被跳过。
- 因此「布线阶段违例 0」之后的下一句可以升级为：两份 GDS 在 41 个制造相关层上逐层一致。

局限（不掩饰）：
- 这是 run 结束后补做的比对，不是流水线第 37 步当时的产物；两者用的是同一套 KLayout 库、同一对 GDS。
- 本机 KLayout 的 Ruby DRC 引擎（-r xxx.drc 这条路）初始化即崩（tlFileUtils.cc:979），
  所以 Magic DRC 数量、KLayout signoff DRC 数量仍然无法补跑，metrics.csv 里那三列仍是 -1。
- 本报告不做 DRC 规则检查，只做「两份产出是否几何一致」这一件事。

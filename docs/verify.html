这一版没有的

  • 没重跑 RCX + 三 corner STA 与 DRV，所以时序结论属于上一版（ctsfix3）原版，不能顺延到这一版
  • 上一版跑 STA 的那一次，DRV 五列是 -1（没跑，不是 0）；真正跑过 DRV 的派生版还留 90 条 max slew
  • LVS 两侧 34,289 与上一版 34,182 差 +107，没追到单元级，照写不抹平

逐条原文、字节数与 sha256 在 evidence/README.md；被推翻的旧写法留在 项目详情里，用「此处更正」标出，不覆盖。

这页能证明什么，不能证明什么

能证明

  • 交付的摘要值，和标准 SHA-256 定义一致
  • 任意长度（含跨块）都对，不只是四组固定向量
  • 两条独立实现互验，改一条另一条立刻不一致（上面那个按钮就是证据）
  • 这一页的输入取自仓库，指纹现场可算、可与 GitHub 同一文件对照
  • 整件事零成本可复现，不装工具链

不能证明

  • 版图做对了、DRC 干净、时序收敛——那是 KLayout、XOR 与 STA 的事；物理侧证据在上节，这页一个都没验
  • 面积、频率、功耗这些数字
  • 硬件在硅上真跑过（这几代都是开源 PDK 的流片级交付，不是实物芯片）
  • 这页的 JS 实现和 RTL 在电路层等价——只证明算法行为一致
  • 指纹只证明「你现在看到的就是仓库里那份」，不证明那份内容本身对——那要靠回归用例

完整验收要跑 scripts/verify_driver.sh，或看 CI 的九个步骤。这页只是把门槛降到「点开就能看一眼」。

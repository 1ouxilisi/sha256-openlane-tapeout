你的 flow 卡住了，我按次给根因

我不卖芯片，也不卖 PPT。卖的是「把一件卡住的事查到底」：可观察的症状、进程级证据、被证死的误判、 能跑的修法、可复现的验证、以及明确的边界。下面每一档都写清交付物和不要什么—— 你先看能不能接受这个标准，再谈钱。

我不接什么

写清楚比写漂亮有用。下面这些直说不做，省得双方浪费时间。

不接原因
商业 EDA 工具（Innovus / ICC2 / Calibre / Tessent）没有授权，也没在真实项目里跑过。我不用没做过的东西接活。
ATPG / scan insertion开源的 openroad 与 yosys 这条路我验过，是死路（preview_dft 必崩、无 ATPG pass）。真要做得上商用工具，不是我现在的能力。
流片与制造不做 shuttle 排期、不碰代工厂。我只做到 GDS 与可核对报告。
签核级 signoff 背书开源 PDK 与开源工具链做不出商业签核效力。我给的每个结论都带版本与口径，不冒充 signoff。
纯代跑（「帮我跑一下就行」）跑一遍谁都会。我卖的是定位与收口，不做廉价代跑。

为什么这个价，凭什么信我

不是按小时算的，是按「这个问题值不值得查到底」算的。同一个卡点，你重跑十遍也只是把同一次失败再演十遍；而根因定位一次，后面所有 run 都不再撞同一面墙。

信不信不用听我说，看这些能自己核对的东西：

方法可验上面那个案例页的每一步都能在 仓库 里对上原始证据，包括进程状态读数与修复脚本
项目可验一颗 SHA-256 从 RTL 到 GDS 的八轮迭代，每轮的数字都指到具体报告文件
过程可验八轮里有失败版本：DRC 不通过的、LVS 不匹配的，都留在记录里没有删
代码可验修复脚本随 Release 公开，stdflow-signoff 里能直接下载

如果你要的是「三天交一份看起来很专业的报告」，我不是最合适的。我能保证的是：结论落到读数、修法能跑、边界写清楚、判断错了会说错了。

PORTFOLIO · 一个人 · 用 AI 干活

我不是工程师，
我是把事做成、并让它可被验证的人

四年工业岗位之后离职，现在一个人做。我的工作不是亲手画版图、不是自己跑每一条命令—— 那些重复劳动全部交给 AI 和脚本。我负责三件交不出去的事：定目标与边界、判断交出来的东西是真是假、判断什么时候停。 下面这个项目，就是我用一件事证明这三件事的方式。

1完整闭环：RTL → GDS 全流程
7 代每代只解决一个真问题
6 道质量门，每次提交自动重跑
1 条命令，外人不看文档就能证伪

案例：一颗真的做出来了的 SHA-256 芯片

没有商业 EDA 授权，没有流片预算，没有制造排期。OpenLane 1.1.1 + SkyWater sky130A，全开源工具链。

项目结果
最终工作点55.56 MHz（18 ns，三 corner setup/hold 全正）
面积 / 单元0.4096 mm²（640 × 640 µm die）· 11,475 cells · 利用率 45.77%
物理验证DRC 0（Magic signoff 规则，不含天线与密度）· Magic 与 KLayout 双 GDS 逐层 XOR：21 个制造层全 0 · LVS 通过（口径写在明处）：展平后顶层 166,353 个器件、84,178 条网两侧完全相等，netgen 原文 Circuits match uniquely；口径是井/衬底并入电源（VNB≡VGND、VPB≡VPWR，版图里由 5,496 个 tap 接到电源）。KLayout 侧 signoff DRC 仍为 -1
第 7 代做了什么换掉消息调度结构（16 深循环窗口 → 移位寄存器），同 die 从 41.67 MHz 提到 55.56 MHz（+33%），cells 反而从 12,288 降到 11,475
被这个结果推翻的话项目早期文档里写着「43.9 MHz 是这条 RTL 的上限」——那是旧架构的上限，不是工艺的上限

没做成的部分也在这页上。v1–v4 时序没收敛（v4 nom setup 余量 -7.63 ns，按签核标准不合格）；裸综合对照与 OpenLane 结论符号相反；功耗角名一度标错（6.84 mW 是 Typical 不是 Fastest）。这些不是我丢人的地方，是我判断力的来源。

这份交付凭什么可信

不是「我写它通过它就通过」。三条互不依赖的证据链，任一条断了这个结论就站不住。

① 结构可信

仓库每次 push，在干净的 Ubuntu runner 上重跑 6 道门：功能回归 v6 / v7、独立向量校验、两代静态 lint、驱动级三方对照。

任何人都能看到跑没跑过、绿没绿。

② 数字可信

期望摘要由 Python hashlib 独立算，不用我自己写的常量；两个版图工具出的 GDS 逐层 XOR，不一致就报错。

自己验自己这件事，被结构性地禁掉了。

③ 外人可证伪

不需要懂芯片，也不需要白皮书。三条命令，跑不通就是假的：

bash scripts/verify.sh
bash scripts/verify_driver.sh
python3 scripts/check_vectors.py

最后一层，是把 C 主机驱动打进验证链：C 驱动打出寄存器写序列 → Verilog 主机模型原样发到真 RTL 的 AXI4-Lite 总线上 → hashlib 算期望值。三份实现互不依赖，四条消息全过。这一层同时回答了「别人能不能接手」。

不想开终端？

浏览器里也能验：四个正式回归向量，两条互不依赖的实现（浏览器原生 + 页面自写的分块状态机）分别复算；证据文件从仓库现取并当场算指纹，可与 GitHub 同一文件对照；另有任意输入、200 组随机压测，以及一个「把常量改错一位」的现场演示。

上面那些数字，也都能点开看原文

55.56 MHz、11,475 cells、0.4096 mm²、9.41 mW、setup 与 hold 的每一格，逐条追到 OpenLane 这次 run 的原文行和行号，附证据文件的指纹。流水线里没跑成的那三步，也在这一页上补跑了：42 个层逐一比对，21 个制造层（nwell 到 met5、via、via4 等）XOR 全部为 0，唯一差异是一个不参与制造的 flow 标记层，流水线本身也把它排除；Magic DRC 跑完零条违例（不含天线与密度检查，原文只有两行表头）；LVS 也跑了——Magic 从版图提取晶体管级网表、netgen 对比到第八轮，顶层器件数两侧完全相等（15,593 = 15,593），只剩 47 个 AXI 端口所连的网没配上——这一版又用六次对照实验（头部折行两个方向、单元定义前移、方括号改名、自动匹配、两侧各删 32 个端口）逐个排除，再把 47,087 / 33,984 / 15,588 三个数字的差额拆开（13,103 全是 fill 与 tap，分毫不差），最后把「为什么没过」查到底：上一版归因的「1,795 行实例缺单元名」被自己推翻——那是标准 SPICE 折行，续行拼回去 33,984 / 33,984 全部有单元名；再上一版归因的「端口表整体错位一格」也被推翻——两侧端口表本来就是 98 / 98 且逐字相同，47 个名字在报告里只打印一遍、无重复，说明两个端口表里都有、失败在网这一层（只有端口真缺时 netgen 才打印两遍，这个差别可复跑验证）；这一版再比一层——不看端口名、看端口连着什么，98 个端口里 94 个连到哪个器件的哪个脚都逐字相同，剩下 4 个（bresp / rresp）查清是转换器漏读了网表末尾 4 条 assign 别名；最后把两侧网名集合做差，真正多出来的只有 VNB / VPB 两个网——版图里井与衬底由 5,496 个 tap 直接接电源、Magic 提取时体端并到电源，而网表里这些 tap 引脚是空的、被整批丢掉，于是成了悬空网。把这两个网并入电源重跑，47 行归零：展平后 166,353 个器件、84,178 条网两侧完全相等，netgen 原文 Circuits match uniquely。这个「过」带口径——井/衬底并入电源、叶子单元由 netgen 展平后再比，所以写的是「顶层晶体管级等价」，不是「每个标准单元内部逐管等价」；另一条本该等价的路（把 tap 补回网表）实跑过了，做不成：PDK 里 tapvpwrvgnd_1 只有 VGND/VPWR 两个脚、body 为空，补回 5,496 个仍是 47 行，强加 VNB/VPB 脚仍是 47 行——口径不是可选项，是单元定义逼出来的唯一写法。KLayout 侧的 signoff DRC 也补跑成了：218 个规则类、0 条违例（同一份 GDS、同一个 PDK deck，并加了一个故意违规的正对照证明引擎确实在查）。之前四次「必崩」查错了——tlFileUtils.cc:979 是 KLayout 找不到 /proc/<pid>/exe 时的断言，chroot 里 /proc 是空目录；把那个路径造出来再 exec 就一次通过。层号已对到 PDK 的图层名表，逐层表、命令与复现脚本一并给出。

我怎么干活

既然身份是「驱动 AI 干活的人」，该展示的不是我知道多少，是我每次怎么组织一次工作。

一步做什么
1 定目标一句话说清要什么。「做出一个能打开的 GDS」，不是「研究一下」——目标得能被别人复述。
2 划边界同时说清不做什么：不量产、不做 DFT 扫链、不追完美。边界不写，工期就没有终点。
3 全权交出去跑流程、读日志、写脚本、渲染、排版——重复劳动全交给机器。人只盯两件事：还剩什么、结论对不对。
4 判真假只认互不依赖的证据，不认「我跑通了」。三条：独立复算、双工具互验、外人能一条命令证伪。
5 决定停还是继续每代只改一个变量，改完先判断收益，再决定要不要下一代。不靠惯性往前推。

三个真实事例，都在同一件事里：

当时以为实际是
功耗 6.84 mW 取的是最保守的 Fastest 角其实是 Typical 角。数字没错，标签错了——比最坏情况乐观约 14%。
这条 RTL 到 43.9 MHz 就到底了那是旧架构的上限。第 7 代换掉调度结构后做到 55.56 MHz。
四条消息跑通就算接口没问题还得在陌生机器上用一条命令复现。CI 第 6 道门干的就是这件事。

我不做的事也写清楚：不亲自写每行 RTL，不盯每个日志，不为了一个更漂亮的数字再加一代。

我负责什么，不负责什么

边界写清楚，比能力写得漂亮更有用。

我负责我不负责我的判据
定目标、划边界、切里程碑具体版图细节、每一行 RTL目标是否可被一句话说清，边界是否可被外人检查
判断交付物真假把自己变成工程师有没有一条外人能不看文档推翻它的命令
把重复劳动交给机器亲手跑每一条命令、盯每一个日志换台干净机器、换个人，结论是否还一样
判断什么时候停无限逼近「更完美」再推一代的收益，是否小于它带来的不确定性

这套方法能搬去哪

能迁移的不是知识，是验收结构：每件事都有它自己的「证据载体」。

领域证据载体
芯片GDS + 多角 STA 报告 + DRC + 双工具 XOR
机器人动作包关节轨迹 + 正运动学复算 + 真机/仿真同帧对比
短剧 / 内容成片 + 分镜与成片逐镜一致 + 素材授权链
汽修手册车型/年款/扭矩值可溯源 + 实车一步一验
财务分析每格数字回原始报表 + 口径写明 + 可复算

同一套六条验收动作（来源≥2 且互不依赖 / 换路径结论不变 / 单位口径写全 / 失败能定位到具体步骤 / 重跑稳定 / 存在外人能推翻它的命令）在五个领域都成立。这份东西写成了手册： 《外行验收手册》。

归属与授权

开源不是把东西送掉，是把使用权按条款让出去，署名权和文档权留着。三层分开写清楚，比一句「版权所有」有用。

代码（脚本、驱动、CI 配置）Apache-2.0。可商用、可修改，保留版权声明与许可文本即可。
硬件（RTL 与 GDSII）CERN-OHL-P-2.0。可用于商业设计，须保留署名与出处。
文档与作品集（项目报告、验收手册、本 PDF、本网页）著作权保留。允许原样转发与引用（须署名 + 原始链接）；不允许修改后署名他人、打包售卖、作为付费课程或培训素材、用于资质投标材料中的虚报。

为什么不把文档也开源

代码可以被人拿去用，方法不能被人拿去当自己的资历。一个人做出来的东西，最值钱的不是文件，是「这件事是他做的」这个事实。

不开公司也能有产权

著作权自作品完成时产生，不需要登记，自然人就是权利人；公开仓库的每一次提交都带时间戳，这就是时间证据。开公司是经营需要，不是拥有作品的前提。

广度是什么

不是把五件事都做一半，是知道哪一件已经能交付、哪一件还只是想法——这两件事中间，差的是能不能被人验证。

找我做什么

只做能交付、且能被验证的事。

适合找我

· 一件模糊的事，需要有人定目标、切里程碑，然后把它跑成可验证的交付

· 你的团队已经在用 AI 干活，但没人判断交付真假——我帮你搭验收结构

· 需要一个「从零到能打开、能检查」的完整案例，而不是一份方案

不适合找我

· 需要资质签字、需要承担法律责任的鉴定与认证

· 需要长期驻场、需要我假装是科班工程师

· 只需要「看起来很像」的素材，不需要真的能跑
